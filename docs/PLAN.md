# Lecture Studio 開発計画書

**バージョン:** 0.1.0（初版）  
**作成日:** 2026年10月9日  
**開発形態:** 個人開発・ローカル運用  
**対象環境:** Windows 11 / WSL2 Ubuntu  
**開発方針:** ChatGPT Plusの既存契約を活用し、追加の月額費用を抑える

---

## 1. プロジェクト概要

### 1.1 目的

大学の講義資料（PDF）を入力として、AIが講義内容を分析し、図解アニメーションと日本語ナレーションを組み合わせた教育動画を自動生成するアプリケーション「Lecture Studio」を開発する。

長文の授業解説を読む負担を減らし、映像・音声によって直感的に理解できる学習環境の実現を目指す。

### 1.2 基本コンセプト

**「PDFをアップロードするだけで、授業がわかる動画になる」**

アプリケーションの利用者は、ブラウザから講義PDFをアップロードし、動画の長さ・解説レベル・映像スタイルを指定する。

システムは、資料解析からMP4生成までの工程を一括して実行する。

### 1.3 開発対象

- 情報工学・コンピュータ科学分野を中心とする大学講義
- 日本語のPDF資料
- 5〜30分程度の教育動画
- 一般的なノートPC・デスクトップPCのブラウザから操作可能なローカルWebアプリ

### 1.4 対象外

- YouTubeなどへの動画投稿
- 定期的な自動実行
- SNS運用機能
- クラウドでの一般公開
- 複数ユーザーでの共同利用
- 実写の人物や高品質な3D映像の生成

## 2. システム構成

### 2.1 採用技術

| 分野 | 採用技術 |
|---|---|
| フロントエンド | React / TypeScript / Vite |
| バックエンド | Python / FastAPI |
| PDF解析 | PyMuPDF |
| AI分析・台本作成 | Codex CLI |
| 動画制作 | Remotion |
| アニメーション | React / SVG / CSS |
| 数式表示 | KaTeX |
| グラフ | SVGまたはRecharts |
| 音声合成 | VOICEVOX ENGINE |
| 音声・映像処理 | FFmpeg |
| データ管理 | SQLite |
| 開発環境 | WSL2 Ubuntu |
| バージョン管理 | Git |

### 2.2 処理フロー

1. PDFアップロード
2. PDFから文章・画像・ページ情報を抽出
3. 解析結果をCodex CLIに渡す
4. AIが講義内容・学習目標・重要概念を分析
5. AIが台本とシーン構成をJSONで生成
6. JSONの構造と内容を検証
7. VOICEVOXでシーンごとの音声を生成
8. 音声の実際の長さから各シーンの表示時間を決定
9. Remotionで図解アニメーションを生成
10. 動画と音声を同期してMP4に書き出す
11. ブラウザでプレビュー・保存

各工程の結果は保存し、途中で失敗した場合も必要な工程だけを再実行できるようにする。

## 3. 機能要件

### 3.1 PDFアップロード・解析

**必須機能**

- 単一PDFのアップロード
- ページ数と基本情報の取得
- 文章の抽出
- 図表・画像の抽出
- 見出しとページ構造の推定
- ファイルサイズ・ページ数制限
- 解析不能なページの検出

**追加機能**

- 複数PDFの統合
- ページ範囲指定
- OCRによる画像PDFへの対応
- 数式・表の高度な構造解析

単なるテキスト抽出では図表の意味が失われる可能性があるため、元PDFのページ画像も参照できる構造とする。

### 3.2 AIによる講義分析

Codex CLIで以下を実行する。

- 学習目標の特定
- 重要語句の抽出
- 概念間の関係分析
- 初学者に必要な前提知識の補足
- 理解の難しい概念の特定
- 適切な説明順序の設計
- 具体例の生成
- 授業全体の構成作成

AIの出力はJSON Schemaで定義し、形式が不正な場合は再生成または修正する。

各解説内容には可能な限り元PDFの参照ページを保持する。資料に根拠がない補足説明は、資料本文に由来する説明と区別する。

### 3.3 解説台本生成

動画は以下の構成を基本とする。

1. 導入・学習目標
2. 必要な前提知識
3. 概念の説明
4. 仕組みの視覚的解説
5. 具体例・応用例
6. 重要事項の復習

指定した動画の長さに応じて内容の詳しさを調整する。

ただし、指定時間に収めるために重要事項を不自然に省略することは避ける。

**台本データ**

- シーンID
- シーンタイトル
- ナレーション原稿
- 説明対象の概念
- 使用する図解の種類
- 図解の内容
- アニメーションの指示
- 参照PDFページ
- 推定所要時間

### 3.4 図解アニメーション生成

初期バージョンでは、AIが任意のプログラムコードを生成する方式ではなく、**事前定義されたアニメーション部品をAIが選択・設定する方式**を採用する。

**実装する図解部品**

| 図解の種類 | 使用例 |
|---|---|
| フローチャート | アルゴリズム・処理手順 |
| 状態遷移図 | OSのプロセス管理 |
| ブロック図 | CPU・メモリ構成 |
| ネットワーク図 | パケット通信 |
| タイムライン | 処理の時間的変化 |
| 比較表 | 技術・方式の比較 |
| 数式アニメーション | 計算過程 |
| キーワード図解 | 用語の関係整理 |

アニメーションには、フェードイン、移動、拡大縮小、強調表示、矢印描画、順次表示などを用いる。

AIが生成した図解データは型検証し、想定外のレイアウトやレンダリングエラーを減らす。

### 3.5 日本語ナレーション

VOICEVOX ENGINEを使用し、ローカル環境で音声を合成する。

- 話者の選択
- 読み上げ速度の調整
- シーンごとの音声生成
- 音声ファイルのキャッシュ
- 原稿修正後の部分再生成
- 読み間違いを修正する辞書機能

音声の自然さを重視し、文章を短すぎる単位に分割しない。

音声の実時間とシーン表示時間を同期させ、ナレーション終了前にシーンが切り替わらないようにする。

### 3.6 動画生成・再生

**初期出力仕様**

- 動画形式：MP4
- 映像コーデック：H.264
- 解像度：1920×1080
- フレームレート：30fps
- 音声：日本語
- アスペクト比：16:9

以下の機能を提供する。

- 生成進捗表示
- 動画プレビュー
- シーク操作
- チャプターごとの再生
- MP4ダウンロード
- 生成済み動画の履歴表示
- レンダリング失敗時のエラー表示

## 4. ユーザーインターフェース

### 4.1 ホーム画面

PDFアップロードを中心としたシンプルな画面とする。

設定項目：

| 設定 | 選択肢 |
|---|---|
| 動画の長さ | 5〜10分 / 15〜20分 / 30分以上 |
| 解説レベル | 初学者 / 標準 / 詳細 |
| 映像スタイル | ホワイトボード / モーショングラフィックス / 図解スライド |
| ナレーション | 話者・速度 |
| 対象範囲 | PDF全体 / 指定ページ |

「生成開始」を押すと制作処理が始まる。

### 4.2 生成画面

現在実行中の工程を表示する。

- PDF解析中
- AIによる講義分析中
- 台本作成中
- 音声生成中
- 図解・動画生成中
- 完了

進捗率は取得できる工程について表示し、根拠のないパーセンテージは表示しない。

エラー時には原因と再試行ボタンを表示する。

### 4.3 動画視聴画面

動画プレーヤーとチャプター一覧を表示する。

初期バージョンでは通常再生を中心とし、将来的に台本表示・字幕・PDF参照機能を追加する。

### 4.4 動画管理画面

生成した動画を一覧表示する。

保存項目：

- 講義タイトル
- 元PDF
- 生成日時
- 動画の長さ
- 生成設定
- 処理状態
- 出力MP4のパス

削除・再生成・再生が可能。

## 5. AI連携方式

### 5.1 基本方針

既存のChatGPT Plus契約を活用するため、初期実装ではChatGPTアカウントで認証したCodex CLIの利用を検証する。

**重要な制約**

- ChatGPT PlusはOpenAI APIの無料利用枠を意味しない
- Codex CLIには利用量制限がある
- Codex CLIは汎用LLM APIではない
- CLIの出力仕様・認証方式・自動実行上の制約を事前検証する必要がある

そのため、AI処理部分には抽象インターフェースを設ける。

### 5.2 AIプロバイダー設計

共通インターフェース `LectureAnalyzer` を用意する。

初期実装：

- `CodexCLIAnalyzer`

将来の追加候補：

- `OpenAIAPIAnalyzer`
- `GeminiAPIAnalyzer`
- `ManualJSONAnalyzer`

これにより、AIの利用方法を変更しても、動画生成部分を作り直さずに済む。

### 5.3 CLI実行管理

バックエンドからCLIを実行する場合は、以下を必須とする。

- 引数配列による安全なプロセス起動
- 実行時間上限
- 同時実行数の制限
- 出力データのJSON Schema検証
- 実行ログの記録
- 失敗時の安全な再試行
- 任意のシェルコマンド実行を許可しない設定
- ファイルの読み書き先の制限

PDFは信頼できない入力として扱い、資料本文に書かれた命令をAIへの実行指示として取り扱わない。

## 6. データ設計

### 6.1 データ構造

主要なエンティティ：

**Project**

- id
- title
- source_pdf
- settings
- created_at
- status

**Scene**

- id
- project_id
- order
- title
- narration
- visual_type
- visual_data
- source_pages
- duration

**Asset**

- id
- scene_id
- asset_type
- file_path
- generation_status

**RenderJob**

- id
- project_id
- status
- progress
- output_path
- error_message

### 6.2 JSON形式

各シーンは次のような構造とする。

```json
{
  "id": "scene_003",
  "title": "プロセスの状態遷移",
  "source_pages": [8, 9],
  "narration": "プロセスは実行可能状態から実行状態に移ります。",
  "visual": {
    "type": "state_diagram",
    "nodes": [
      {"id": "ready", "label": "実行可能"},
      {"id": "running", "label": "実行"}
    ],
    "edges": [
      {"from": "ready", "to": "running"}
    ],
    "steps": [
      {"action": "highlight_node", "target": "ready"},
      {"action": "highlight_edge", "target": "ready-running"},
      {"action": "highlight_node", "target": "running"}
    ]
  }
}
```

実際の表示時間は音声生成後に決定する。

## 9. 非機能要件

### 9.1 性能

- 生成処理がブラウザのリクエスト時間制限に依存しないこと
- 長時間処理はバックグラウンドジョブとして管理すること
- 動画生成中もUIが応答すること
- 同一素材・同一設定での再生成時はキャッシュを活用すること

※ここでいうバックグラウンドジョブは、利用者が生成ボタンを押した後にアプリ内部で実行する処理であり、定期的な自動起動ではない。

### 9.2 セキュリティ

- ローカルホストへのバインドを基本とする
- PDFアップロード時に拡張子・実体・容量を検証する
- 任意コード実行を避ける
- ファイルパスを正規化する
- PDF・プロンプト・AI生成データを信頼しない
- 不要な機密情報をログに残さない
- 外部AIへ送信する内容を明確にする

### 9.3 信頼性

- 処理失敗時に原因を確認できること
- 生成途中の成果物を保持できること
- 不正なAI出力を検出できること
- 音声と映像の長さが一致すること
- PDFに存在しない情報の断定を抑制すること
- 自動生成した教材には誤りがあり得ることを明示すること

## 10. 品質評価とテスト

### 10.1 テスト対象

- テキスト中心のPDF
- 図表の多いPDF
- 数式を含むPDF
- フローチャートを含むPDF
- ページ数が多いPDF
- 一部の文字を抽出できないPDF

### 10.2 評価項目

| 項目 | 評価基準 |
|---|---|
| 正確性 | 元資料と矛盾する説明がない |
| 網羅性 | 重要概念が適切に含まれる |
| 説明の明瞭さ | 初学者が理解しやすい |
| 視覚表現 | 図解がナレーションに対応 |
| 音声品質 | 読み間違いや不自然な分割が少ない |
| 同期品質 | 音声と画面がずれない |
| 安定性 | 失敗時に復旧・再実行できる |

### 10.3 初期受け入れ基準

- 5〜10分程度の動画を最後まで生成できる
- 生成MP4が一般的なプレーヤーで再生できる
- 主要なシーンで図解アニメーションが使われている
- 参照ページを確認できる
- 音声・映像同期に重大なずれがない
- 例外発生時にエラーメッセージが表示される

## 13. 開発方針と優先順位

開発で最も重要なのは、豪華なUIではなく、**教材として正確で、見て理解しやすい動画を安定生成できること**である。

優先順位：

1. PDF解析とAI連携の成立
2. 台本・シーン構造の安定化
3. 音声と図解の同期
4. 動画品質の向上
5. UI・編集機能の充実

初期段階では、1分程度の技術検証動画を確実に生成できる状態を作ってから、長尺動画やWeb UIの機能を拡張する。

## 14. 最終目標

Lecture Studioの最終的な体験は次のとおりとする。

**講義PDFをアップロード → 動画の設定を選択 → 生成開始 → 日本語の図解アニメーション講義を視聴**

将来的には、動画を見て理解できなかった部分を追加指示で再解説させたり、対応するObsidianノートや確認問題を生成したりできる、個人用のAI学習環境への発展を目指す。
